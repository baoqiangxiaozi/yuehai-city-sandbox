# 粤海街道 3D 沙盘 · 验收报告

分支 `cursor/yuehai-v4-blender-landmarks-fc28`。本报告只记录这一分支上的结果，没有合并，没有部署，没有推送 `main`。

## 和仓库、v4 包的关系

仓库原来的单页和 v4 源码包使用同一份 OSM JSON（SHA256 `8b621052a50f7ce7c66328f8d9532a5dd521296f8416d199ddbdf6a80f8e670d`）。v4 在此之上增加了内联的 Three.js r128、漫游、普通楼 LOD、启动失败的中文提示，以及腾讯滨海、华润两座 Blender 模型。这些都保留了。

仓库原有的 GitHub Pages 工作流和 `.nojekyll` 也保留。本分支不推 `main`，因此不会触发 Pages。

Three.js 仍是 r128，SHA256 `9274bbcec8d96168626c732b5d31c775aa8cfb7eaa0599bec0c175908a2c1ce2`。没有升级 Three，没有新增运行时依赖，没有高斯泼溅，没有在线更新 OSM。

## 腾讯滨海大厦改了什么

上一版（锯齿幕墙、铜门架、大裙楼、暴露桁架，约 28748 三角面）已从页面移除，新模型不会和它叠在一起。

新模型 5326 三角面：

- 南塔、北塔使用 OSM 轮廓和高度 245.8 米 / 194.8 米，朝向烘焙在顶点里。没有改成百科上的 248 米。
- 幕墙是浅色玻璃上的横档和竖梃。横档约 0.9 米高、竖梃约 0.62 米宽，间距比真实幕墙更疏，否则整栋入画时格子会小于一个像素。这是沙盘放大，不是实测模数。
- 三条水平连廊：低连廊 22–58 米（按街景，近似），中连廊为南塔 21–25 层，高连廊为南塔 35–38 层。连廊是深色体，带约 2.2 米的铜色边框和玻璃侧板。边框加粗同样是为了能看清，不是实测杆件。
- 平屋顶。没有大裙楼，没有桁架。

无头 Chrome 里，把周围楼暂时隐藏后，侧向镜头能同时看到两座完整塔身和上、中、下三道连廊，用的是资产本身的颜色：`close/tencent-binhai-32-a.png`、`close/tencent-binhai-32-b.png`。放回城市后的 `close/tencent-in-city.png` 仍能认出双塔，但一栋通用楼挡住了低连廊的下半段。上一轮的红色核对帧不再作为本轮结论。

## 页面行为

- 旧的专用 JS 构建体已停用，包括会把口岸、保利、海岸城再画一遍的修复函数。通用楼会跳过这些地标的 OSM 索引，所以底下没有第二套棱柱。
- 拾取、地标卡、夜景、环境反射和建筑图层仍然接到这些模型。建筑图层关闭时，模型的父组不可见。
- 普通楼 LOD 仍是 160 米分块、250 毫秒节流、近景 180/240 米、中景 600/720 米。测试里通用楼计为 2221 栋、491 块。这比早期口头说的 2212 多，因为口岸附近若干未命名低楼没有被划进口岸模型，仍作为通用楼保留。
- 漫游没有碰撞，视高固定，可以穿过建筑和水面。HUD 上写了这句话。
- 车流等数字仍标为模拟。

## 没有核实或没有测到的部分

- 无头 SwiftShader 在会话末尾报告约 2 FPS，自动画质降到低档（阴影关、环境反射无）。当时总览大约 325 次绘制、349000 三角面。这是软件渲染的数字，不是桌面显卡的帧率，也不能当成页面在用户机器上已经达标。
- 无头环境的动画帧不稳定，所以没有用两次短按来证明 Shift 恰好是 4 倍。4 倍写在 `yuehai.roam.js` 里，并由 `tests/roam.test.js` 覆盖。这一轮浏览器里只确认 W 能移动、Esc 能回到总览。R、失焦清键和 Shift 没有在这一轮浏览器里再测。
- 这一轮没有再测 390 像素宽的触控垫，也没有再测 LOD 的近景/中景切换。上一轮的记录仍在旧截图里，但不算本轮质量改动之后的复测。
- 拖动转向和滚轮缩放没有逐项录成单独截图。轨道相机在 Esc 之后处于启用状态。
- 连廊的米制标高、腾讯大厦平面、春茧跨度、万象城体量、大家保险腰线、百度连廊楼层都是近似，见 `landmarks/ASSET_NOTES.md`。
- 没有在真机手机上操作。
