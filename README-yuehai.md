# 粤海：山海之间的科技城（当前主页 · 单文件版）

> 下文是开发历史。当前页面已经去掉第一人称漫游，镜头和标名建筑的现状见根 `README.md`。以下内容不作为新功能验收。

> 本文件记录粤海单文件版的实现细节和开发过程。当前可运行入口是根目录的 `index.html`。
> 本包不含前海升级版（`qianhai.html`、`README-qianhai.md` 等），也不含 `artifacts/` 验收截图；
> 下文若出现这些路径，只是历史记录，不是本包文件。
> 文中的帧率、draw call 和「实测」数字来自当时的开发机器，**不是当前成绩**，请勿当作现测结果。

单文件 Three.js 3D 城市沙盘。页面是构建出的 `index.html`，已内联 Three.js r128，
可直接用浏览器打开，无需访问 CDN。源码在 `src/`，数据在 `data/yuehai-osm.json`，
库文件在 `vendor/three.min.js`。重新构建请运行 `python scripts/build_page.py`。

## 1. OSM 数据统计

原始 Overpass Turbo 导出文件（本包未收录，路径仅作历史记录）：曾位于开发者本机 `export.geojson`，日期 2026-10-28。本包使用的是处理后的 `data/yuehai-osm.json`。

| 类型 | 识别方式 | 输入要素 | 处理后 |
|---|---|---:|---:|
| 道路 | `highway=*` | 902 | 897 段 |
| 建筑 | `building=*` | 2453 | 2419 栋 |
| 地铁 | `railway=subway` | 76 | 按需求渲染 2 / 13 号线 |
| 水域 | `natural=water` / `water=*` | 27 | 27 个水面 |
| 合计 |  | 3458 |  |

- 建筑清洗：外轮廓简化（约 0.55 m）、面积 `< 70 m²` 的棚体过滤；轨道交通站房
  轮廓不重复挤出为普通楼块，改用地铁站标记。
- 道路清洗：按项目范围裁切、折线简化；保留 `名称 / 等级 / 车道数 / 限速 / 坐标`。
- 高度：优先 `height`；无 height 时用 `building:levels × 3.2 m`；都没有时稳定随机
  3–8 层。垂直方向有视觉夸张，便于低多边形沙盘阅读。
- 地铁：只渲染 OSM 中可用的 2 号线、13 号线；站点取 2/13 线附近的 6 个站房。
- 信号灯：数据中有 90 个 OSM 信号候选点，吸附到路口图后得到 **89 个信号控制节点**。
- 处理后 JSON：`data/yuehai-osm.json`，**635,580 bytes（0.606 MiB，< 2 MB）**，
  坐标保留 1 位小数（米）。

这些均为 OpenStreetMap 开放数据，页面角落已标注
`© OpenStreetMap contributors` 并链接到 ODbL 版权页。

## 2. 坐标与数据结构

平面原点取**建筑轮廓包围盒中心**（不使用贯穿全图的高架/地铁长线造成的极端外包围盒）：

- 原点：`113.92678415°, 22.5203268°`
- 投影：`x = (lon - lon0) × 111320 × cos(lat0)` 米（东向）
  `z = (lat0 - lat) × 110540` 米（南向）
- 场景范围：x `[-2520, 2520]` m，z `[-2520, 2320]` m；北为 `-z`。

`data/yuehai-osm.json` 的压缩字段：

```js
{
  meta:     { origin, projection, scope_m, counts, ... },
  roads:    [ { n: 名称, c: 等级, l: 车道数, s: 限速(km/h), p: [x,z,x,z,...] } ],
  buildings:[ { height: 米, levels: 层数, t: 类型, n: 名称, p: [x,z,...] } ],
  water:    [ { kind: 水体类型, name: 名称, points: [x,z,...] } ],
  subway:   [ { line: 线路号, name, color, paths: [[x,z,...], ...] } ],
  stations: [ { name, x, z, lines: [...] } ],
  signals:  [ [x,z], ... ],
  landmarks:[ { id, name, en, x, z, buildings: [建筑索引], source, note } ]
}
```

## 3. 修改方式

### 替换 OSM 数据 / 移动建筑

本包不含从 GeoJSON 重新投影的 `scripts/build_yuehai_data.py`。当前数据就是
已经处理好的 `data/yuehai-osm.json`（约 635,580 字节，2026-10-28）。

只调整个别建筑：编辑 JSON 对应建筑的 `p` 坐标（米，`[x,z]` 成对；x 东、z 南）
或 `height`，然后运行 `python scripts/build_page.py` 重建页面。也可以直接改
`index.html` 中 `id="osm-data"` 的 JSON，但不要用格式化编辑器破坏 JSON 结构。
不要在线拉取或覆盖整份 OSM 数据。

地标位置由 `landmarks` 中的 `x/z` 和 `LANDMARK_COPY`（JS 内）共同控制。无 OSM
轮廓的「腾讯大厦」「深圳湾万象城」「科技园片区」保留为金色近似锚点，并在 UI 中
明确注明。要删除/调整锚点，可修改 `landmarks` 数组与 `LANDMARK_COPY`。

### 修改路网

道路就是 `roads[].p` 中成对的平面米制折线。页面加载时会自动重新建立：

- 路网吸附节点：`nodeKeyOf()` / `trafficNodes`；
- 车辆图：`txEdges`（边属性：名称、等级、车道数、限速、长度、主干权重）；
- 车辆在当前道路末端按权重选择下一条边（早高峰偏向科技园/写字楼，晚高峰偏向
  居住区与地铁站）；
- 信号灯：`DATA.signals` 吸附到图节点，形成 89 个信号路口，30s 绿 / 3s 黄 /
  30s 红双相位；车辆在停止线前排队。

道路节点的建图逻辑和信号灯相位在 `src/yuehai.js` 的 `CITY TRAFFIC V2` 段。
新增/修改道路后，车辆图会自动重建。本包没有数据构建脚本；若要改信号灯位置，
请直接编辑 `data/yuehai-osm.json` 中的 `signals` 后重新运行 `scripts/build_page.py`。

页面的 `NODES 935 · EDGES 897 · SIGNALS 89` 就是运行时生成的路网图规模。

### 修改配色

- **UI / 面板 / 强调色**：`index.html` 顶部 CSS 的 `:root`：
  `--bg`、`--panel`、`--gold`、`--gold-bright`、`--line` 等。
- **建筑立面**：JS 中的 `COLORS`（`glassA/glassB/resi/retail/...`）以及
  `buildBuildings()` 里的 `typeColors`、`typeRoof`。
- **道路与拥堵色带**：`roadColorsByClass` 是静态路面颜色；实时色带在
  `txUpdateCongestionColors()` 中按通畅度映射
  `CONGESTION_RED / AMBER / YELLOW / GREEN`。
- **天空 / 雾 / 日夜**：`SKY_STOPS`（午夜深蓝、黎明/黄昏橙粉、白天淡蓝）、
  `computeLight()`、`autoLightPower()`、`WEATHER` 中的 `fog`/`sun` 参数。
- **海面**：`waterMat` 的片元着色器里 `deep` / `shallow`、`uLightPower` 与夜景反射项。
- **地铁**：`line_colors`（生成数据时）与 JS 中线路颜色。

### 第三轮：昼夜、灯光、天气与世界控制

- **昼夜**：时间轴 00:00–24:00 驱动太阳；6:30 日出、18:30 日落，正午最强，
  夜间由独立的低强度月光补光。`isNight` 在 19:00–06:00 为 true。
  天空/雾按 `SKY_STOPS` 插值，昼夜、黄昏、天气都通过每帧缓动过渡。
- **窗灯**：约 21,600 个窗面合并为一个 `InstancedMesh`；每扇窗有确定性种子，
  随机亮灭。写字楼 22:00 后逐步熄灯，居住区 23:00 后逐步熄灯，03:00 仅约
  12% 窗面保留。所有建筑（OSM 或手写数据）都经过字段归一化后再生成窗灯。
- **玻璃幕墙**：主要商业/公共/高层建筑额外叠加一层自定义 Fresnel 深灰玻璃壳，
  带楼层与竖向分格反射；玻璃位于窗灯前，使灯光呈现“室内透出幕墙”的层次。
- **重点地标玻璃盒**：腾讯滨海、百度国际、软件产业基地的 22 个 OSM 体块改用
  独立的不透明幕墙 shader（保留原轮廓，替换原窗灯与通用玻璃）：深灰反射玻璃、
  竖向鳍线、按层采样的暖金/冷白办公内透，窗层与工位随机留暗，夜间不再是一整片
  均匀的 LED 网格。
- **中国华润大厦（春笋）定制模型**：已回退到上一版精模——392.5 m 的
  96 段 Lathe 春笋曲面、48 道线鳍、V 形基座、四道技术环和暖金/冷白内透
  shader。OSM 原通用棱柱已移除，保留“中国华润大厦”地标标签、卡片与点击/跟随。
- **路灯**：主干道等距 1,928 盏，灯柱/发光球为两个 `InstancedMesh`，光晕为
  一个 Points 光晕层；不使用真实点光源。
- **车灯**：每辆车的两盏前灯和两盏尾灯各用一个 `InstancedMesh`，夜间自发光。
- **地标**：腾讯滨海、百度国际、软件产业基地、中国华润大厦叠加轮廓/顶部角灯；
  全城创建 7 个真实 `PointLight`（4 个地标 + 3 个主要路口，≤ 8）。
- **水面**：深圳湾 shader 增加 `uLightPower`，夜间叠加金色/青色发光倒影带；
  关灯时倒影同步消失。
- **灯光三档**：自动（跟随昼夜与窗灯时刻表）/ 开启（常亮）/ 关闭。
  图层“夜景灯光”与这三档状态均独立工作。
- **天气**：晴朗 / 多云 / 小雨 / 暴雨 / 雾天。雨线最多 8,000 条并跟随相机；
  多云降低直射光 20%，低多边形云缓慢漂移；雾天提高 `FogExp2` 密度；暴雨
  降低曝光、加深路面、偶发闪电。切换约 2 秒完成。
- **天气联动**：`weatherFactor` 为晴 1.0 / 多云 0.98 / 小雨 0.85 / 雾 0.75 /
  暴雨 0.60，直接乘车辆目标速度和生成率；数据栏同步体现。
- **交通基础（沿用上一轮）**：1500 辆容量池、峰值约 1200 辆；固定 1/30 s
  物理步长，每帧最多 12 次子步；需求曲线在 `txDemandAt()` 中分段实现；
  89 个信号路口（30 / 3 / 30 双相位）；GUI 平均速度来自自行车速。
- **世界控制**：右侧毛玻璃面板包含光阴、天气、灯光、图层、镜头、画质六个
  分区；图层含建筑 / 路网 / 地铁 / 车流 / 拥堵色带 / 信号灯 / 夜景灯光 /
  停车占用 / 地标标注，各自独立。
- **镜头**：自由 / 自动环绕 / 跟随地标。自动环绕拖动即暂停，3 秒无操作恢复；
  “跟随地标”下拉可平滑飞向地标并慢速环绕；拖动会取消当前飞行。所有切换
  使用缓动目标，不瞬移。
- **沉浸视角**：右面板顶部按钮隐藏全部界面，只留场景；按 Esc 或右上角
  “退出沉浸”恢复。
- **画质**：自动 / 流畅 / 均衡 / 精美。自动档按帧率连续 3 秒 < 30 FPS 降档；
  手动选档后锁定，不再自动降级。切换只改阴影开关、阴影图尺寸、环境反射与
  像素采样，不重建场景。
- **建筑兼容**：加载后会归一化 `p / points / polygon / footprint` 以及
  `height / h / levels`、`t / type`；手写建筑也可以用 `x,z,w,d` 矩形描述。
  建筑主体仍按真实 footprint 合并为单次绘制（比逐栋实例更省 draw call），
  窗面、雨、车、路灯等重复元素使用 `InstancedMesh`。

### 第四轮：真实阴影与 PBR 环境反射

- **阴影**：`renderer.shadowMap.enabled=true`，类型 `PCFSoftShadowMap`；全场只有
  `sun` 这一盏方向光投射阴影。建筑主体、屋顶、树木、路灯杆、公交站、地铁站体量、
  春笋塔楼均 `castShadow`；地面、道路、广场 `receiveShadow`。
- **阴影相机**：正交范围 ±350 m（约 700 m 见方），跟随 `controls.target`，
  在光源空间按阴影图纹素对齐后移动，避免相机平移时闪烁；精美 2048、均衡 1024、
  流畅关闭。太阳按 06:30–18:30 弧线走，清晨/黄昏长影，正午短影；夜间同一盏灯
  切换为 `#b8c9da` 的弱蓝月光（强度 0.20），阴影保留但变淡。
- **环境贴图**：Canvas 程序生成 day / dusk / night 三组天空立方体贴图（顶部深蓝→
  地平线浅蓝→地面深灰，侧向带深色城市剪影与云带），无外部 HDR。精美档
  `scene.environment` 全场景启用；均衡档只给玻璃材质；流畅档关闭。
- **材质分工**：玻璃幕墙 `MeshPhysicalMaterial`：`metalness=.9`、
  `roughness=.10`、`envMapIntensity=1.2`，真实反射天空和对面楼体块；石材/混凝土
  `metalness=0`、`roughness=.85`、`envMapIntensity=.25`；金属构件
  `metalness=.85`、`roughness=.35`。百度国际 / 软件产业基地 / 春笋的
  自定义玻璃 shader 也采样同一环境贴图。
- **色调**：ACESFilmicToneMapping、曝光 1.05、`outputEncoding=sRGBEncoding`。
- **低档**：关闭真实阴影，切到楼脚 `InstancedMesh` 接触阴影（假 AO）；环境反射关闭。
- **验收图**：`artifacts/final2-light-noon.png`、`artifacts/final2-light-dusk.png`、
  `artifacts/final2-light-dusk-low.png`、`artifacts/final2-light-night.png`。
- **历史实测（开发机器记录，不是当前成绩）**：1440×900、RTX 4060 Laptop、ANGLE D3D11；精美档 12:00 约 226 FPS、
  18:00 约 233 FPS、23:00 约 233 FPS，阴影 pass 总 draw call 148；流畅档
  18:00 约 230 FPS，总 draw call 135。该场景在当前 GPU 上还有余量，开关阴影的
  FPS 差异不大，主要差异是 13 个阴影相关 draw call 与阴影图 2048/1024/关。

### 第五轮：腾讯滨海大厦精模

只精模一栋：`tencent-binhai`。锚点仍取 `landmarks` 中的
`(373.9, -602.0)`；两座塔楼的高度和轮廓分别取 `buildings[602]`
（南塔 245.8 m）和 `buildings[603]`（北塔 194.8 m），没有改点位、没有抬高地坪。

- **双塔**：南塔、北塔按数据高度各自挤出。平面不是方盒，而是 `THREE.Shape`
  圆角矩形沿 Y 挤出，四角为圆弧（场景半径约 0.64）。南塔高、北塔矮，屋顶各自
  有比塔身宽出 0.6 m 的银灰冠带薄板，冠带下沿有独立夜间发光条。
- **三道连廊**：位置取南塔高度的 **0.32 / 0.55 / 0.78（近似比例）**，即约
  79 m / 135 m / 192 m。每道连廊由上下弦杆、竖杆、交叉斜腹杆、两端横向封边和
  底部斜撑组成真实桁架盒，并带深色玻璃匣；杆件两端伸入塔身 0.1 场景单位，
  是真的连接而不是贴着表面。连廊底边有独立暖白灯带，夜间随 `lightPower` 亮起。
- **立面**：银灰竖向遮阳鳍片共 **254 根**，位于两塔的东西向长边，间距
  1.2 m（场景 1.2×PLAN）；短边整面深色玻璃，不布鳍片。鳍片为真实薄盒几何，
  用单个 `InstancedMesh` 绘制，因此既有实体厚度与投影，又不增加逐根 draw call。
- **裙楼与大堂**：底部三层层高连体裙楼（3×4.2 m），外轮廓包住两塔，中央用
  圆角矩形洞口围合下沉广场，洞口下方有下沉地坪；三条楼层横带让三层可读。
  主入口上方有横向挑檐，挑檐由两根细钢柱支撑。
- **材质**：塔身/连廊玻璃 `MeshPhysicalMaterial`：`metalness=.9`、
  `roughness=.14`、`envMapIntensity=1.2`；鳍片、冠带、桁架、挑檐
  `metalness=.85`、`roughness=.35` 银灰金属；裙楼石材 `metalness=0`、
  `roughness=.85`、`envMapIntensity=.25`。
- **预算与增量**：两塔 + 连廊 + 裙楼 + 冠带 + 鳍片合计 **5,262 三角形**
  （≤40,000）；主渲染新增 **7 个 draw call**（141 vs 原 134，≤10）。7 个 mesh 为
  南塔、北塔、裙楼、下沉地坪、金属实例、连廊玻璃实例、夜间灯带实例。
- **拾取/标签**：双塔、裙楼、连廊玻璃都写入 `customLandmarkId`，点选后仍打开
  “腾讯滨海大厦”地标卡；原 602/603 的通用棱柱和窗面已从 OSM 主体合批中跳过。
- **验收图**（为看清构件，截图时临时隐藏周边程序化楼体，仅保留地面；三维点位

  通过 `DATA.landmarks` / `CAMPUS_SKIP_INDICES` 排除，不覆盖。
- **点式塔**：长宽比 <1.6 且高 ≥60 m，共 **898 栋**；四面窗带，
  长面每层一道 0.25 m 薄阳台板，短面窗带。
- **板式塔**：长宽比 ≥1.6，共 **537 栋**；长面通层阳台线，
  约 15 m 一道竖向楼梯间实墙带；短面窗带。
- **两色制**：4 个暖灰/米白色系轮换；墙用 vertex colors，
  阳台/女儿墙/屋顶设备深一号；单栋三角形均远低于 2,500。
- **屋顶**：平顶 + 女儿墙 + 1 个设备盒；无散放。
- **裙房/字牌**：数据中无明确裙房记录，未编造商业体量；普通塔楼
  仅做入口小雨棚/绿化带。
- **窗户**：四面共享 4 个朝向的 Canvas 窗模板；窗只占格子约 60%，
  19% 稀疏亮窗、30% 整层暗带；`lightPower` 统一开关，白天 0。
- **预算**：新增 **7 draw call**（≤40），住宅组合计 **195,668 三角形**；
  单栋均 ≤2,500。
- **验收图**：`res-coast-night.png`（蔚蓝海岸 48 栋同系统）、

### 第五十六轮：全城住宅统一化回退

### 第六十一轮：楼顶标签分级与避让

- **分级维护**：写死在 `yuehai.js` 的 `LABEL_TIER1 / LABEL_TIER2`
  名称清单；未命中清单的 landmark 落 **tier 3**。新建精模时把名称加入
  对应清单即可，不需要改模型数据。
- **相机分档**：tier1 全城可见；tier2 仅在相机距锚点 ≤185 时出现；
  tier3 永不自动出现。
- **同屏上限**：自动标签 ≤14；按 tier、离屏幕中心距离、相机距离排序。
- **防压盖**：不做 y 轴硬错位；按屏幕包围盒计算重叠面积 / 较小面积，
  >40% 时隐藏低优先级标签。
- **兜底**：悬停/点选的 landmark 强制显示；普通 building 用临时
  `hoverBuildingChip`，锚在楼高 2/3 以内；强制项可突破上限/级别。
- **密度三档**：精简（只 tier1）/ 标准（默认，tier1 + 近景 tier2）/
  全部（所有级别，仍受 14 上限和避让约束）；`localStorage` 持久化。
  旧「地标标注」开关保留为总开关，关闭时三档都不显示。
- **远景样式**：tier1 远于 260 时字号约 10px、半透明底；近景恢复。
- **地铁小标签**：保留原逻辑，并纳入同一 40% 屏幕避让。
- **实测**：总标签 42；tier1 16、tier2 15、tier3 11；
  远景可见 **14**；近景标准 **7**、全部 **12**。
- **证据**：`labels-far3.png`、`labels-near-final.png`、
  `labels-all-final.png`。

## 4. 文件

- `index.html` — 完整单文件页面（内嵌数据 / CSS / JS / Three.js r128），可脱机打开
- `data/yuehai-osm.json` — 压缩后的投影数据
- `vendor/three.min.js` — 固定版本 Three.js r128，构建时内联进 `index.html`
- `scripts/build_page.py` — 把数据、源码和 vendor 合成单文件
- `src/` — 可维护的 CSS / HTML / JS 源片段。当前页面没有第一人称漫游控制器。
- `README.md` — 本包实际文件与打开 / 构建方式

本包不含 `scripts/build_yuehai_data.py`，也不含前海版文件或 `artifacts/` 截图。
运行构建脚本无需安装第三方 Python 依赖，只用标准库。
